# Feature map

What Trelis can do today, where each piece lives, and what is planned. Read this before exploring the code. Terms are the ones in `GLOSSARY.md`; decisions are in `docs/adr/`. Paths in backticks are checked by `scripts/check-feature-map.sh` (run by `make lint`), so a renamed or deleted file fails the build until this map is updated.

Status: **done** (built, tested, reachable), **partial** (code exists but nothing in the running service calls it yet), **planned** (only an issue).

## System at a glance

- **One Go process**, `cmd/server`, serves the HTTP API and runs the admin CLI (`trelis admin ...`). The binary is `trelis` (`bin/trelis` from `make build`, `/trelis` in the image); in development `go run ./cmd/server` runs it. Ingest runs as a Temporal workflow (ADR-0005), served by two workers inside the same process: the ingest work, and model calls on their own rate-limited queue.
- **Stores** (`compose.yaml`, `compose.dev.yaml`):
  - Postgres (ParadeDB image, `pgvector` and `pg_search`): the source of truth (ADR-0002). Schema in `migrations/`, applied by goose on every start.
  - S3-compatible object storage (silo in dev): Source Files, later Figures (ADR-0006).
  - Neo4j: a rebuildable graph projection (ADR-0002). Only probed by `/readyz` today.
  - Temporal: runs the ingest workflow (ADR-0005); also probed by `/readyz`.
- **Layers** (ADR-0007): `internal/router` (chi, middleware) → `internal/handler` (HTTP ↔ service) → `internal/application/service` (use cases, transactions) → `internal/application/repository` (Postgres through `db.Store`) → `internal/db` (sqlc queries, `ExecTx`). Contracts between layers are in `internal/types/interfaces`; domain types in `internal/types`.
- **A request's path**: `requestID` → `accessLog` → `recoverer` (`internal/router/logging.go`) → `authenticate` (`internal/router/authn.go`, puts the Principal in the context) → handler → service (checks the Access List) → repository.

## Model clients

Each role (`models.chat`, `models.extraction`, `models.judge`, `models.embedding`, `models.rerank`) points at its own OpenAI-compatible provider; config in `internal/config/models.go`, documented in `config/trelis.yaml`. Every call logs one `model call` line (`internal/logger/modelcall.go`). The embedding client is called by the ingest embed-batch activities and dense retrieval; the rerank client is called by retrieval when a request names rerank; the chat client is called by the Pipeline Answer service. The extraction and judge clients are **partial**.

A provider status 401, 402, 403 or 429 — its credentials, credit, permission or rate limit — becomes a 502 `ErrModelProvider` (`internal/models/providererror/`), with a message that names the model role and never the provider's body; any other provider failure stays a generic 500. The original `*api.HTTPError` stays in the chain, so ingest still classifies a failed batch by `api.HTTPStatusCode`.
